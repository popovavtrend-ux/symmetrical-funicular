# Расчёт и обрезка маршрута доставки

Автоматизация построения дневного маршрута курьера по маршрутному листу
(xlsx): реальный расчёт км/времени через OSRM, оптимизация порядка точек
развоза, обрезка маршрута по лимиту оплаченного объёма (70 км / 4 ч).

## Что делает

1. **Читает маршрутный лист** (`parse_route_sheet.py`) — заказы, адреса,
   контакты, часы работы/приёмки. Заказы на один и тот же адрес объединяются
   в одну точку (вес суммируется).
2. **Геокодирует адреса** (`geocode.py`) через Nominatim/OpenStreetMap,
   с локальным кэшем (`delivery_route/cache/geocode_cache.json`), чтобы не
   геокодировать одно и то же каждый день. Ненадёжные результаты (нет номера
   дома, слишком общий тип объекта, низкая уверенность геокодера) помечаются
   `needs_review`, и в интерактивном режиме скрипт спрашивает подтверждение.
3. **Строит маршрут** (`route_builder.py`): старт и финиш — фиксированная
   точка склада, обязательные пикапы — в заданном вами порядке, точки
   развоза — оптимизируются через OSRM Trip API (с фолбэком на эвристику
   ближайший сосед + 2-opt по матрице OSRM Table API, если Trip недоступен).
4. **Обрезает маршрут по лимиту** (`limiter.py`): нарастающий пробег/время
   считаются по реальным данным OSRM Route API; после 70 км или 4 часов
   (что раньше) — оставшиеся точки уходят в "сверх лимита".
5. **Формирует отчёт** (`report.py`): ссылка на Яндекс.Навигатор для
   основного маршрута, список точек сверх лимита с весом, итоговые км/время
   (основной и полный маршрут), список всех точек с комментариями по
   времени работы/приёмки.

## Запуск

```bash
pip install -r requirements.txt

python -m delivery_route.cli \
  --xlsx "маршрутный_лист.xlsx" \
  --pickup "Химический пер., 1" \
  --output route_report.txt
```

Полезные флаги:

- `--pickup "адрес"` — обязательная точка в начале маршрута (можно указать
  несколько раз, порядок = порядок в маршруте; их порядок не оптимизируется).
- `--max-km` / `--max-hours` — лимит оплаченного объёма (по умолчанию 70 / 4).
- `--non-interactive` — не спрашивать подтверждение неточных координат
  (такие точки просто помечаются и не включаются в маршрут).
- `--user-agent` — свой контакт для запросов к Nominatim (см. их
  [политику использования](https://operations.osmfoundation.org/policies/nominatim/));
  можно также задать через переменную окружения `GEOCODER_USER_AGENT`.
- `--start-lat` / `--start-lon` / `--start-label` — переопределить точку
  склада (по умолчанию пр. Большевиков, 42к2В, 59.889070, 30.491275).

## Важно про данные

Маршрутные листы содержат реальные адреса, телефоны и суммы клиентов
компании — **не коммитьте сами xlsx-файлы и заполненный кэш геокодирования
в git**, если репозиторий не приватный лично для вас. Директория
`delivery_route/cache/` (кроме `.gitkeep`) уже добавлена в `.gitignore`.

## Ограничения

- Публичный OSRM-сервер (`router.project-osrm.org`) — бесплатный, но без
  SLA; при перегрузке или сетевых сбоях скрипт не падает, а либо переходит
  на эвристику (порядок точек), либо на приблизительную оценку км/времени
  по прямой (это явно помечается в отчёте как "⚠ приблизительно").
- Геокодирование через публичный Nominatim ограничено ~1 запросом в секунду
  — скрипт это учитывает автоматически.
