# symmetrical-funicular

Бот, который:
1. берёт новости из нескольких RSS-лент англоязычных крипто-СМИ и переводит
   их на русский (по умолчанию — [Protos](https://protos.com) и
   [DL News](https://www.dlnews.com), см. ниже почему);
2. берёт новости из нескольких RSS-лент русскоязычных крипто-СМИ и постит
   как есть, без перевода (по умолчанию — [INCRYPTED](https://incrypted.com)
   и [Криптовалюта.Tech](https://cryptocurrency.tech));
3. отслеживает посты в X (Twitter) известных людей из крипто-мира и пишет по
   ним короткие новостные посты на русском.

Источников для каждого языка может быть сколько угодно — `FEED_URL`/
`RU_FEED_URL` принимают список через запятую.

Публикуется весь текст, который отдаёт сама RSS-лента источника (без
искусственной обрезки, только с запасом под лимит Telegram в 4096 символов),
плюс ссылка на статью в виде слова **Источник**. Работает по расписанию
через GitHub Actions, без своего сервера.

## Почему именно эти источники, а не CoinDesk/Cointelegraph/Forklog/РБК Крипто

Крупные англо- и русскоязычные крипто-СМИ (CoinDesk, Cointelegraph, Decrypt,
Unchained Crypto, Forklog, РБК Крипто, Bits.media и т.п.) уже активно
репостятся/переводятся десятками телеграм-каналов — контент будет
дублироваться. **Protos** и **DL News** (англоязычные, расследования/DeFi/
регулирование), **INCRYPTED** и **Криптовалюта.Tech** (русскоязычные,
среднего размера) — для всех на момент проверки не нашлось широко известных
каналов-дублёров. Список источников легко поменять/расширить через
`FEED_URL` (англ.) / `RU_FEED_URL` (рус.) — см. настройку ниже.

## Как это устроено

### Новости (RSS → Telegram)

- `fetch_feed.py` — читает одну или несколько RSS-лент (`FEED_URL` через
  запятую). Лента, которая не отвечает или отдаёт битый XML, просто
  пропускается (с логом) — остальные всё равно постятся.
- `main.py` — объединяет записи из всех лент, сортирует по дате публикации
  (а не по порядку источников), затем постит.
- `translate.py` — переводит заголовок/описание. Если задан `ANTHROPIC_API_KEY`,
  используется Claude (лучше справляется с крипто-терминологией); иначе —
  бесплатный Google Translate через `deep-translator`.
- `state.py` / `data/seen_ids.json` — хранит id уже опубликованных новостей.
- `.github/workflows/post_news.yml` — запускает бота каждые 30 минут.

### Русскоязычные новости (RSS → Telegram, без перевода)

Тот же `main.py`, но с `SKIP_TRANSLATION=true` — публикует заголовок и
описание как есть, без обращения к translate.py.

- `data/seen_ru_ids.json` — отдельный файл состояния (не пересекается с
  англоязычными источниками).
- `.github/workflows/post_ru_news.yml` — запускает бота каждые 30 минут.
  Источники задаются через `RU_FEED_URL` (по умолчанию — INCRYPTED +
  Криптовалюта.Tech).

### Посты из X (Twitter) → Telegram

- `x_accounts.py` — список отслеживаемых аккаунтов (по умолчанию: Vitalik
  Buterin, CZ, Michael Saylor, Anthony Pompliano, Arthur Hayes, Brian
  Armstrong, Balaji Srinivasan, Wu Blockchain). Меняется через `X_ACCOUNTS`.
- `x_source.py` — получает последние посты аккаунта. Если задан
  `X_BEARER_TOKEN` — через официальный X API (платный, но надёжный,
  от $200/мес за Basic-тариф). Иначе — через публичные Nitter-зеркала
  (бесплатно, но нестабильно: зеркала регулярно падают/блокируются, чтение
  чужих постов через них не одобрено правилами X, поэтому в какой-то момент
  это может просто перестать работать — тогда потребуется платный API).
- `compose.py` — не просто переводит, а составляет короткий новостной пост на
  русском по мотивам твита (через Claude, если задан `ANTHROPIC_API_KEY`;
  иначе — просто перевод текста).
- `data/seen_tweets.json` — хранит id уже опубликованных постов по каждому
  аккаунту.
- `.github/workflows/post_tweets.yml` — запускает бота каждые 15 минут.

Все боты при первом запуске на новом источнике/аккаунте только "сидируют"
текущее состояние без публикации — чтобы не завалить канал всем архивом сразу.
Нюанс: у новостных ботов "сидирование" привязано к файлу состояния целиком, а
не к каждой ленте по отдельности — если добавить новую ленту в `FEED_URL`
уже работающему боту, её текущие записи (до `MAX_ITEMS_PER_RUN`, по
умолчанию 5) один раз попадут в канал как "новые", а не засеются молча.

## Настройка

1. **Создайте Telegram-бота**: напишите [@BotFather](https://t.me/BotFather),
   команда `/newbot`, сохраните токен.
2. **Добавьте бота администратором** в ваш канал (с правом публиковать сообщения).
3. **Узнайте chat_id канала**: проще всего через `@username` канала (если он
   публичный) — тогда `TELEGRAM_CHAT_ID` = `@your_channel`. Для приватного
   канала chat_id можно получить, переслав любое сообщение из канала боту
   [@getidsbot](https://t.me/getidsbot) или через `getUpdates` Bot API.
4. В настройках репозитория **Settings → Secrets and variables → Actions**
   добавьте secrets:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `ANTHROPIC_API_KEY` (опционально, для перевода через Claude)
5. По желанию задайте **variables**:
   - `FEED_URL` — список англоязычных RSS через запятую (по умолчанию
     `https://protos.com/feed/,https://www.dlnews.com/rss/`)
   - `RU_FEED_URL` — то же самое, список русскоязычных RSS через запятую
     (по умолчанию `https://incrypted.com/feed/,https://cryptocurrency.tech/feed/`)
   - `X_ACCOUNTS` — список аккаунтов X через запятую (по умолчанию — список
     в `x_accounts.py`)
   - `NITTER_INSTANCES` — свои Nitter-зеркала через запятую, если дефолтные
     не работают
6. Для мониторинга X при желании добавьте secret `X_BEARER_TOKEN` (официальный
   платный API — надёжнее, чем бесплатные Nitter-зеркала).
7. Запустите все три workflow вручную (вкладка Actions → выбрать workflow →
   Run workflow) для первого "посева" состояния, дальше они тикают сами
   (новости и рус. новости — каждые 30 минут, посты из X — каждые 15 минут).

## Локальный запуск

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_CHAT_ID=@your_channel
python main.py          # англоязычные новости с переводом (Protos + DL News)
SKIP_TRANSLATION=true FEED_URL=https://incrypted.com/feed/,https://cryptocurrency.tech/feed/ STATE_FILE=data/seen_ru_ids.json python main.py  # рус. новости без перевода
python post_tweets.py   # посты из X
```

## Имитация корпоративного чата (юрист + главбух)

Отдельная фича, не связанная с новостным ботом: приватная Telegram-группа,
где кроме вас сидят два бота-персонажа — «юрист» и «главный бухгалтер». Вы
задаёте вопрос в группе, боты читают его через GitHub Actions и отвечают
каждый от своего лица через ИИ (Claude по умолчанию, можно переключить на
DeepSeek).

### Как это устроено

- `corp_chat.py` — раз в 5 минут (по расписанию Actions) опрашивает чат
  через Telegram `getUpdates`, определяет новые сообщения от живых людей и
  генерирует на них ответы.
- Если сообщение — реплай на сообщение конкретного бота, или в тексте есть
  `@username` одного из ботов — отвечает только он. Иначе отвечают оба, каждый
  по своей части, не повторяя друг друга.
- `corp_chat_config.py` — описание персонажей (имя, роль, провайдер ИИ,
  модель) — всё переопределяется переменными окружения, менять код не нужно.
- `corp_chat_ai.py` — генерация ответа через Claude или DeepSeek.
- `data/corp_chat_state.json` — id последнего обработанного апдейта +
  короткая история переписки для контекста ответов; коммитится обратно в
  репозиторий тем же способом, что и состояние новостных ботов.

**Важно:** GitHub Actions по расписанию не гарантирует точный интервал (по
факту это скорее «раз в 5–15 минут», иногда дольше в моменты нагрузки на
GitHub) — это не мгновенный чат-бот, ответа стоит ждать не сразу, а в течение
нескольких минут. Для настоящего реального времени нужен свой постоянно
работающий процесс (сервер/VPS) вместо расписания — можно перейти на это
позже, если задержка окажется неудобной.

### Настройка

1. Создайте **двух ботов** через [@BotFather](https://t.me/BotFather)
   (`/newbot` дважды) — один будет «юристом», другой «главбухом». Сохраните
   оба токена.
2. Для каждого бота у BotFather выполните `/setprivacy` → выберите бота →
   **Disable** — иначе бот не увидит сообщения в группе, которые явно не
   адресованы ему.
3. Создайте приватную Telegram-группу, добавьте туда себя и обоих ботов
   (админские права ботам не нужны).
4. Узнайте chat_id группы — перешлите любое сообщение из группы боту
   [@getidsbot](https://t.me/getidsbot), либо посмотрите `getUpdates` любого
   из ботов после первого сообщения в группе.
5. В **Settings → Secrets and variables → Actions** добавьте secrets:
   - `TELEGRAM_BOT_TOKEN_LAWYER`, `TELEGRAM_BOT_TOKEN_ACCOUNTANT`
   - `TELEGRAM_CHAT_ID_CORP` (chat_id группы, обычно отрицательное число)
   - `ANTHROPIC_API_KEY` (уже может быть настроен для новостного бота)
   - `DEEPSEEK_API_KEY` — опционально, если какой-то из персонажей должен
     отвечать через DeepSeek
6. По желанию задайте **variables**:
   - `LAWYER_NAME`, `ACCOUNTANT_NAME` — как персонажи подписываются в
     промпте (сами имена в Telegram всё равно берутся из профиля бота —
     задайте их через `/setname` у BotFather)
   - `LAWYER_PROVIDER`, `ACCOUNTANT_PROVIDER` — `anthropic` (по умолчанию)
     или `deepseek`
   - `LAWYER_MODEL`, `ACCOUNTANT_MODEL`, `LAWYER_ROLE`, `ACCOUNTANT_ROLE` —
     точная модель / описание роли, если дефолтные не подходят
7. Запустите workflow `Corporate chat simulation (Telegram)` вручную (Actions
   → Run workflow) один раз для первого "посева" — он не будет отвечать на
   уже накопившиеся в группе сообщения, только на новые после этого запуска.

### Локальный запуск (разово, для проверки)

```bash
export TELEGRAM_CHAT_ID_CORP=-1001234567890
export TELEGRAM_BOT_TOKEN_LAWYER=...
export TELEGRAM_BOT_TOKEN_ACCOUNTANT=...
export ANTHROPIC_API_KEY=...
python corp_chat.py
```

Каждый запуск — это один "тик" опроса (не бесконечный процесс), поэтому для
проверки удобно просто вызывать `python corp_chat.py` руками после того, как
написали сообщение в группу.

## Важно про авторские права

Бот публикует только то, что источник сам уже отдаёт публично через свою
RSS-ленту (заголовок и `<description>`) — он не скрейпит и не копирует
полный текст статьи со страницы сайта. Многие издания сами решают, сколько
текста класть в RSS: одни отдают статью целиком, другие — только краткий
анонс, вынуждая переходить по ссылке. Что бы ни отдавала лента источника —
именно столько и попадёт в пост, плюс кликабельная ссылка "Источник" на
оригинал.
