# symmetrical-funicular

Бот для Telegram-канала **Fresh Live**, который:
1. берёт новости из нескольких RSS-лент англоязычных крипто-СМИ и делает
   рерайт на русском (`FEED_URL`);
2. берёт новости из нескольких RSS-лент русскоязычных крипто-СМИ и делает
   такой же рерайт (`RU_FEED_URL`);
3. раз в день публикует отдельный обучающий пост на одну из базовых тем
   крипто-ликбеза (что такое блокчейн, кошелёк, стейкинг и т.п.) — по кругу,
   без привязки к конкретной новости.

Новости чередуются между двумя стилями подряд от поста к посту (opinion →
explainer → opinion → ...): **opinion** — короткое личное мнение от первого
лица; **explainer** — подробное объяснение простыми словами для читателя без
бэкграунда в крипте/финансах, без финансовых советов, с расшифровкой каждого
термина. Оба без выдумывания фактов/цифр, которых не было в источнике, но с
сохранением всей конкретики из источника (цифры, имена, даты) — рерайт не
должен схлопывать новость до общей мысли ради краткости. Именованные монеты,
тикеры и организации оформляются как хэштеги (#Bitcoin, #SEC) — по ним удобно
искать посты внутри канала.

Публикуется весь рерайт целиком, без обрезки под лимит Telegram — если текст
не влезает в подпись к фото (1024 символа), фото уходит без подписи, а полный
текст — отдельным сообщением следом. Плюс строка "По материалам: <источник>"
как обязательная атрибуция первоисточника. Работает по расписанию через
GitHub Actions, без своего сервера.

## Как это устроено

- `fetch_feed.py` — читает одну или несколько RSS-лент (`FEED_URL` через
  запятую). Лента, которая не отвечает или отдаёт битый XML, просто
  пропускается (с логом) — остальные всё равно постятся.
- `main.py` — объединяет записи из всех лент, сортирует по дате публикации,
  отсеивает дайджесты/роундапы и почти дублирующие друг друга заголовки из
  разных источников, затем постит.
- `translate.py` — рерайт заголовка/описания через Claude, чередуя стили
  opinion/explainer от поста к посту (`state.py` хранит, какой стиль был
  последним); если `ANTHROPIC_API_KEY` не задан или Claude недоступен —
  фолбэк на бесплатный Google Translate через `deep-translator` (уже без
  рерайта и без чередования, просто перевод как есть).
- `stock_image.py` / `price_chart.py` — подбор иллюстрации: для конкретной
  монеты рисуется её реальный график цены, иначе — стоковое фото. Поисковый
  запрос не статичный: Claude читает саму новость (заголовок + описание) и
  формулирует запрос по смыслу истории (взлом, суд, регуляторика, обвал
  цены и т.п.), а не просто по названию монеты — так разные новости про один
  и тот же токен не сваливаются в один и тот же запрос и не тянут одну и ту
  же картинку. Фото ищутся сразу по нескольким банкам (Pexels + опционально
  Unsplash/Pixabay, если заданы ключи) с максимальным per_page и
  перемешиванием результатов — это расширяет пул кандидатов, из которого
  выбирается ещё не использованное недавно фото (история — в
  `data/*_images.json`).
- `state.py` / `data/seen_ids_channel.json`, `data/seen_ru_ids_channel.json`
  — хранят id уже опубликованных новостей (отдельно для каждого языка).
- `.github/workflows/post_news_channel.yml` — EN-новости, каждые 2 часа.
- `.github/workflows/post_ru_news_channel.yml` — RU-новости (без обращения к
  переводу источника — те уже на русском), каждые 2 часа.

### Обучающие посты

- `education_topics.py` — список тем, по кругу.
- `post_education.py` / `data/education_state.json` — какая тема была
  следующей.
- `.github/workflows/post_education.yml` — раз в день.

### Обзор рынка

Шесть отдельных постов в день (08:00–08:15 МСК, с шагом в несколько минут,
чтобы не отправлять всё разом), каждый — свой источник и своя тема. Первый
из них (крипта, в 08:00) открывается приветствием «Доброе утро! Обзор
рынка» — остальные пять идут без него, чтобы не повторять его в каждом
отдельном сообщении. Общая логика получения/форматирования данных — в
`market_data.py`, посты — тонкие обёртки над ним. Везде — 🟢/🔴 вместо
цвета (в Telegram HTML нет цветного
текста), у акций рядом с тикером — название бумаги (#SBER (Сбербанк)), а
где уместно — изменение в рублях рядом с процентом, в одну строку на
инструмент. Каждый раздел независим — если источник недоступен,
соответствующий пост просто не публикуется в этот день, на остальные пять
это не влияет.

Пять постов из шести (все, кроме крипты) по будням: биржи, которые они
описывают, по выходным не работают, и публиковать в субботу/воскресенье
те же цифры пятницы с нулевым изменением незачем — это проверяется дважды,
расписанием cron (`* * 1-5`) и на всякий случай ещё раз в коде
(`market_data.is_trading_day_msk`). Крипта публикуется каждый день, включая
выходные, — рынок торгуется круглосуточно:

- `post_market_crypto.py` (CoinGecko, без ключа) — капитализация рынка и
  альткоинов (минус Bitcoin), капитализация DeFi, курсы BTC/ETH, топ-3
  роста/падения за сутки среди топ-100 монет по капитализации (чтобы в
  лидеры не попадали неликвидные микрокапы со случайным +400%).
- `post_market_currency.py` (MOEX ISS, без ключа) — курс USD/EUR/CNY к
  рублю, **биржевые** котировки (не дневной фиксинг ЦБ РФ), с изменением
  в рублях и процентах.
- `post_market_metals.py` — золото/серебро биржевые (MOEX ISS, без ключа);
  платина/палладий — на дневном фиксинге ЦБ РФ (свободного биржевого
  источника для них не нашлось), у них изменение день-к-дню, а не
  внутридневное — это явно указано в самой строке поста.
- `post_market_indices_world.py` (Yahoo Finance, без ключа) — S&P 500,
  Dow Jones, Nasdaq.
- `post_market_indices_ru.py` (MOEX ISS, без ключа) — IMOEX, RTS.
- `post_market_stocks.py` — топ-3 роста/падения акций России (MOEX ISS,
  без ключа, ликвидные бумаги режима TQBR, с названием компании рядом с
  тикером) и топ-3 роста/падения акций мира (Financial Modeling Prep,
  нужен `FMP_API_KEY` — бесплатный тариф на financialmodelingprep.com
  хватает с запасом на 1 запрос/день; без ключа раздел по миру просто
  пропускается).
- `.github/workflows/post_market_*.yml` — расписание каждого поста.

### Мониторинг резких движений

Два отдельных workflow отслеживают те же инструменты в течение торгового
дня и публикуют алерт **немедленно**, вне расписания дайджеста, если
что-то вышло за порог — сравнение идёт не с ценой открытия дня, а с ценой
на момент последнего алерта (после срабатывания точка отсчёта сбрасывается
на текущую цену). Состояние (последняя цена по каждому инструменту) — в
`data/market_watch_*_state.json`, коммитится обратно в репозиторий каждым
запуском. При первом запуске (или при появлении нового инструмента)
проверка только "сеет" точку отсчёта, без алерта — иначе первый же запуск
сравнивал бы цену с нулём.

- `market_watch_crypto.py` — Bitcoin и Ethereum, порог **3%**. Остальные
  монеты тут не отслеживаются — они рутинно двигаются на 3%+, для них
  есть топ-движения в дневном дайджесте, а не отдельный алерт. Раз в 2
  часа, круглосуточно (крипта не закрывается).
- `market_watch_traditional.py` — валюта USD/EUR/CNY к рублю (**1%**),
  золото/серебро (**2%**), индексы США и России (**1.5%**), отдельные
  акции России по MOEX TQBR (**5%**). Акции мира тут не отслеживаются —
  бесплатный тариф Financial Modeling Prep даёт только список топ-движений,
  без котировки конкретного тикера, от которой можно вести свою точку
  отсчёта. Раз в 2 часа, только по будням и только в часы реальных торгов
  (проверяется дважды: расписанием cron и на всякий случай ещё раз в коде
  — `market_data.moex_session_open`/`us_session_open`) — валюта/золото-
  серебро/индексы и акции России считаются только пока открыта MOEX
  (10:00–19:00 МСК), индексы США — пока открыта биржа США (16:00–23:00
  МСК).
- `.github/workflows/market_watch_crypto.yml`,
  `.github/workflows/market_watch_traditional.yml` — расписания.

Ни дайджест, ни мониторинг не обращаются к Claude — это чистые числовые
данные из публичных API, без единого вызова LLM.

### Описание канала и закреп

- `set_description.py` — разовый скрипт: выставляет описание канала и
  публикует + закрепляет приветственное сообщение с объяснением, что есть в
  канале. Запускается вручную через
  `.github/workflows/set_description.yml`. Без разбора — можно запускать
  ещё раз, но это отправит новое приветствие поверх старого, а не обновит
  уже закреплённое.

Все боты при первом запуске на новом источнике только "сидируют" текущее
состояние без публикации — чтобы не завалить канал всем архивом сразу.
Нюанс: "сидирование" привязано к файлу состояния целиком, а не к каждой ленте
по отдельности — если добавить новую ленту в `FEED_URL` уже работающему боту,
её текущие записи (до `MAX_ITEMS_PER_RUN`) один раз попадут в канал как
"новые", а не засеются молча.

## Настройка

1. **Создайте Telegram-бота**: напишите [@BotFather](https://t.me/BotFather),
   команда `/newbot`, сохраните токен.
2. **Добавьте бота администратором** в ваш канал (с правом публиковать сообщения).
3. **Узнайте chat_id канала**: проще всего через `@username` канала (если он
   публичный) — тогда `TELEGRAM_CHAT_ID` = `@your_channel`. Для приватного
   канала chat_id можно получить, переслав любое сообщение из канала боту
   [@getidsbot](https://t.me/getidsbot) или через `getUpdates` Bot API.
4. В настройках репозитория **Settings → Secrets and variables → Actions**
   добавьте secrets:
   - `TELEGRAM_BOT_TOKEN_2`
   - `TELEGRAM_CHAT_ID_2`
   - `ANTHROPIC_API_KEY` (для рерайта через Claude — без него бот только
     переводит текст как есть, без адаптации под новичков)
   - `PEXELS_API_KEY` (для подбора иллюстраций)
   - `UNSPLASH_ACCESS_KEY`, `PIXABAY_API_KEY` — опционально, второй и третий
     банк фото в дополнение к Pexels (оба бесплатные:
     unsplash.com/developers, pixabay.com/api/docs) — без них бот работает
     только через Pexels
   - `FMP_API_KEY` — опционально, для раздела «лидеры роста/падения акций
     (мир)» в обзоре рынка (бесплатный тариф на financialmodelingprep.com)
     — без него этот раздел просто пропускается, остальной обзор рынка
     публикуется как обычно
5. По желанию задайте **variables**:
   - `CHANNEL_FEED_URL` — список англоязычных RSS через запятую
   - `CHANNEL_RU_FEED_URL` — список русскоязычных RSS через запятую
6. Запустите все три workflow вручную (вкладка Actions → выбрать workflow →
   Run workflow) для первого "посева" состояния, дальше они тикают сами.

## Локальный запуск

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_CHAT_ID=@your_channel
python main.py          # EN-новости с рерайтом
SKIP_TRANSLATION=true FEED_URL=https://incrypted.com/feed/,https://cryptocurrency.tech/feed/ STATE_FILE=data/seen_ru_ids_channel.json python main.py  # RU-новости
python post_education.py  # обучающий пост
```

## Важно про авторские права

Бот публикует только то, что источник сам уже отдаёт публично через свою
RSS-ленту (заголовок и `<description>`) — он не скрейпит и не копирует
полный текст статьи со страницы сайта, а делает собственный рерайт по мотивам
этого краткого содержания. Каждый пост подписан строкой "По материалам:
<источник>" — это и есть указание источника, которое делает рерайт законным
цитированием (ст. 1274 ГК РФ), а не безымянным копированием.
